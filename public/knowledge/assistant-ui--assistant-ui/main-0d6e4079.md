### 2.2 React 挂载层：`AssistantRuntimeProvider`

`AssistantRuntimeProvider` 是一个 `memo` 包裹的函数组件，接收四个 props：`runtime`（必填）、`aui`、`config`、`children`；渲染时直接转交 `AssistantProviderBase`，并把 `aui ?? null` 归一化后传入（[AssistantRuntimeProvider.tsx](https://github.com/assistant-ui/assistant-ui/blob/852a3fa2a61ce81a9161929d12266728dfe7c382/packages/core/src/react/AssistantRuntimeProvider.tsx)）。✅

组件注释给出了它在架构中的角色：

- 把 `AssistantRuntime` 挂载进 React 树；

- 内部安装 `AuiProvider`，使后代可直接使用 `useAui`、`useAuiState`、`useAuiEvent` 与 primitives，无需额外设置（[AssistantRuntimeProvider.tsx](https://github.com/assistant-ui/assistant-ui/blob/852a3fa2a61ce81a9161929d12266728dfe7c382/packages/core/src/react/AssistantRuntimeProvider.tsx)）。✅

### 2.3 运行时适配层：`RuntimeAdapter`

`RuntimeAdapter.ts` 是已读代码中信息密度最高的文件，展示了一个基于 `@assistant-ui/tap` 的 resource 化适配器：

```ts
const useRuntimeAdapter = (runtime: AssistantRuntime) => {
  const clientRef = useAssistantClientRef();
  useAssistantScopeEffect(
    "modelContext",
    () => runtime.registerModelContextProvider(clientRef.current!.modelContext()),
    [runtime],
  );
  return useResource(
    ThreadListClient({
      runtime: runtime.threads,
      __internal_assistantRuntime: runtime,
    }),
  );
};
export const RuntimeAdapter = resource(useRuntimeAdapter);
```

（[RuntimeAdapter.ts](https://github.com/assistant-ui/assistant-ui/blob/852a3fa2a61ce81a9161929d12266728dfe7c382/packages/core/src/react/RuntimeAdapter.ts)）✅

可解析出的结构：

- **resource 化**：`RuntimeAdapter` 由 `resource(useRuntimeAdapter)` 生成，内部用 `useResource(...)` 创建 `ThreadListClient`；`resource`/`useResource` 来自 `@assistant-ui/tap`（[RuntimeAdapter.ts](https://github.com/assistant-ui/assistant-ui/blob/852a3fa2a61ce81a9161929d12266728dfe7c382/packages/core/src/react/RuntimeAdapter.ts)）。✅ 这说明适配器不是普通 React 组件，而是可被资源系统复用的 hook 资源（🔶 “资源系统”的具体语义需读 `@assistant-ui/tap`）。
- **双向注册**：一方面通过 `useAssistantScopeEffect("modelContext", ...)` 把当前 client 的 `modelContext()` 注册给 runtime 的 `runtime.registerModelContextProvider(...)`；另一方面用 `runtime.threads` 构造 `ThreadListClient`，把 runtime 暴露为 `threads` scope（[RuntimeAdapter.ts](https://github.com/assistant-ui/assistant-ui/blob/852a3fa2a61ce81a9161929d12266728dfe7c382/packages/core/src/react/RuntimeAdapter.ts)）。✅ 即运行时与客户端之间是**互相接线**关系，而非单向读取。
- **内部字段**：`ThreadListClient` 额外接收 `__internal_assistantRuntime: runtime`（[RuntimeAdapter.ts](https://github.com/assistant-ui/assistant-ui/blob/852a3fa2a61ce81a9161929d12266728dfe7c382/packages/core/src/react/RuntimeAdapter.ts)）。✅ 双下划线命名表明这是包内约定字段，🔶 其消费方未读取。

**scope 默认值注入**：`runtimeAdapterTransformScopes(scopes, parent)` 先调用 `baseRuntimeAdapterTransformScopes`，再在两个条件下补默认值——当 `scopes.tools` 不存在且 `parent.tools.source === null` 时注入 `Tools({})`；`dataRenderers` 同理注入 `DataRenderers()`（[RuntimeAdapter.ts](https://github.com/assistant-ui/assistant-ui/blob/852a3fa2a61ce81a9161929d12266728dfe7c382/packages/core/src/react/RuntimeAdapter.ts)）。✅ 函数注释说明这是 `RuntimeAdapter` 作为 `threads` 配置项时安装的 scope 默认值，供包装 runtime 的适配器包复用，以保持 scope 一致（[RuntimeAdapter.ts](https://github.com/assistant-ui/assistant-ui/blob/852a3fa2a61ce81a9161929d12266728dfe7c382/packages/core/src/react/RuntimeAdapter.ts)）。✅

最后一行 `attachTransformScopes(useRuntimeAdapter, runtimeAdapterTransformScopes)` 把 transform 函数绑定到该 hook 资源上（[RuntimeAdapter.ts](https://github.com/assistant-ui/assistant-ui/blob/852a3fa2a61ce81a9161929d12266728dfe7c382/packages/core/src/react/RuntimeAdapter.ts)）。✅ 即 scope 补全不是调用方手动做的，而是随适配器注册自动生效。🔶 `attachTransformScopes` 的具体触发时机在 `@assistant-ui/store/client` 中，未覆盖。

### 2.4 事件广播工具：`notify-event-listeners.ts`

该文件只有两个导出：类型 `EventListener<T> = (payload: T) => unknown` 与函数 `notifyEventListeners(listeners, payloadOrFactory, errorContext)`（[notify-event-listeners.ts](https://github.com/assistant-ui/assistant-ui/blob/852a3fa2a61ce81a9161929d12266728dfe7c382/packages/core/src/utils/notify-event-listeners.ts)）。✅

行为要点：

- 对 `listeners`（任意 `Iterable`）逐个调用；
- 若 `payloadOrFactory` 是函数，则先调用它得到 payload 再传给 listener；
- 若 listener 返回 thenable，则 `Promise.resolve(result).catch(reportError)` 捕获异步 rejection；
- 同步抛错被 `try/catch` 捕获；
- 所有错误统一走 `console.error("[assistant-ui] ${errorContext} listener threw an error", error)`，不中断循环（[notify-event-listeners.ts](https://github.com/assistant-ui/assistant-ui/blob/852a3fa2a61ce81a9161929d12266728dfe7c382/packages/core/src/utils/notify-event-listeners.ts)）。✅

源码注释点明了一个刻意的歧义处理：“函数型 payload 与工厂函数无法区分，会被调用；请把函数型 payload 包进工厂函数”（[notify-event-listeners.ts](https://github.com/assistant-ui/assistant-ui/blob/852a3fa2a61ce81a9161929d12266728dfe7c382/packages/core/src/utils/notify-event-listeners.ts)）。✅ 这是该工具最值得注意的 API 陷阱。

## 4. 设计取舍

1. **组合 primitives 而非单体组件**：README 明确把“可组合 primitives + 自带样式”作为与单一聊天组件对立的设计选择，并让 CLI 把 shadcn/ui 主题复制进用户项目（[README.md](https://github.com/assistant-ui/assistant-ui/blob/852a3fa2a61ce81a9161929d12266728dfe7c382/README.md)）。✅ 取舍代价是用户需自行组装 `Thread`/`Message`/`Composer` 等；收益是像素级可控。
2. **Provider 薄壳 + 内部基座**：`AssistantRuntimeProvider` 只做 `memo` 与 `aui ?? null` 归一化，把复杂度推给 `AssistantProviderBase`（[AssistantRuntimeProvider.tsx](https://github.com/assistant-ui/assistant-ui/blob/852a3fa2a61ce81a9161929d12266728dfe7c382/packages/core/src/react/AssistantRuntimeProvider.tsx)）。✅ 好处是公开入口稳定、内部可演进；代价是阅读者必须跳出该文件才能理解安装过程。
3. **适配器以 resource 表达**：`RuntimeAdapter` 走 `resource/useResource` 而非普通组件，且通过 `attachTransformScopes` 自注册默认 scope（[RuntimeAdapter.ts](https://github.com/assistant-ui/assistant-ui/blob/852a3fa2a61ce81a9161929d12266728dfe7c382/packages/core/src/react/RuntimeAdapter.ts)）。✅ 这让“包装 runtime 的适配器包”能复用同一 transform 以保持 scope 一致（源码注释明说，[RuntimeAdapter.ts](https://github.com/assistant-ui/assistant-ui/blob/852a3fa2a61ce81a9161929d12266728dfe7c382/packages/core/src/react/RuntimeAdapter.ts)）；代价是依赖 `@assistant-ui/tap` 与 `@assistant-ui/store` 的隐式生命周期，🔶 不读这两个包难以判断复用与清理语义。
4. **默认值注入带 parent 判空**：只在 `parent.tools.source === null` 时补 `Tools({})`，说明设计上允许父级已提供 tools 时不覆盖（[RuntimeAdapter.ts](https://github.com/assistant-ui/assistant-ui/blob/852a3fa2a61ce81a9161929d12266728dfe7c382/packages/core/src/react/RuntimeAdapter.ts)）。✅ 这是一种“就近优先、缺省兜底”的 scope 合并策略。🔶 `source === null` 与 `scopes.tools` 未定义的语义差异，需要读 `@assistant-ui/store` 才能确认。
5. **事件广播的错误隔离**：单个 listener 抛错或异步 reject 只记录日志，不打断其余 listener，也不向调用方抛出（[notify-event-listeners.ts](https://github.com/assistant-ui/assistant-ui/blob/852a3fa2a61ce81a9161929d12266728dfe7c382/packages/core/src/utils/notify-event-listeners.ts)）。✅ 取舍是健壮性优先于可观测性：错误只进 `console.error`，调用方无法感知失败。🔶 这是否符合预期需看调用方上下文。
6. **`payloadOrFactory` 的运行时判别**：用 `typeof === "function"` 区分 factory 与 payload，导致函数型 payload 必须再包一层工厂（源码注释明确警告，[notify-event-listeners.ts](https://github.com/assistant-ui/assistant-ui/blob/852a3fa2a61ce81a9161929d12266728dfe7c382/packages/core/src/utils/notify-event-listeners.ts)）。✅ 这是为“惰性求值 payload”付出的类型/运行时歧义成本。
7. **质量门禁脚本化**：根清单把 API surface、changeset 语义、adapter 架构、声明产物等做成独立 `check`/`test` 脚本并配套 `*.test.mjs`（[package.json](https://github.com/assistant-ui/assistant-ui/blob/852a3fa2a61ce81a9161929d12266728dfe7c382/package.json)）。✅ 取舍是仓库维护成本上升，换取多包发布时的边界稳定。
