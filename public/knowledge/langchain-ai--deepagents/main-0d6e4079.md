## 1. 项目定位

README 将 Deep Agents 定义为“the batteries-included agent harness”，即开箱即用的 Agent 运行框架，并给出四条原则：有主见、可扩展、模型无关、可用于生产。它明确说明自身构建在 LangGraph 之上，并利用 LangSmith 提供 tracing、评估与部署能力。[README]

README 还给出三层关系：LangGraph 是图运行时；LangChain 的 `create_agent` 是较轻的 Agent harness；Deep Agents 是构建在 `create_agent` 之上的更有主见的 harness，内置文件系统、子 Agent、上下文管理和技能等能力。[README]

README 列出的能力包括：子 Agent、可插拔文件系统后端、上下文管理、Shell 访问、持久记忆、Human-in-the-loop、Skills 和工具集成。安全模型是“trust the LLM”：Agent 能做什么取决于工具边界，因此应在工具/沙箱层限制，而不是期待模型自我约束。[README]

因此，从定位上看，本项目值得研究的主线是：**规划 → 工具调用 → 子任务委派 → 状态持久化 → 长任务执行闭环**。但本次只读到了装配入口、后端协议、记忆中间件和异步子 Agent 的片段；规划、Shell、技能加载等具体实现仍未覆盖。

### 2.2 构造入口与中间件装配

`graph.py` 的模块 docstring 明确：`create_deep_agent` 是主入口，用于构造一个配置完整的 Deep Agent，包含 planning、filesystem、subagent 和 summarization middleware。[graph.py]

从导入清单可以看到，装配层涉及大量中间件与辅助模块，包括：

- `HumanInTheLoopMiddleware`、`InterruptOnConfig`：Human-in-the-loop 中断配置。
- `FilesystemMiddleware`、`FilesystemPermission`：文件系统工具与权限。
- `MemoryMiddleware`、`SkillsMiddleware`：记忆与技能。
- `SubAgentMiddleware`、`AsyncSubAgentMiddleware`：同步与异步子 Agent。
- `create_summarization_middleware`：长上下文摘要。
- `PatchToolCallsMiddleware`、`_ToolExclusionMiddleware`、`UnsupportedContentMiddleware`、`_ParentNotifierMiddleware`、`append_prompt_caching_middleware` 等。[graph.py]

这些导入说明 `create_deep_agent` 不是单一 Agent 循环，而是**围绕 `create_agent` 组合一套中间件栈**。不过，完整函数体在 10,000 字符处被截断，因此不能据此断言最终顺序或每个中间件是否总是启用。

`graph.py` 中的辅助函数提供了若干可确认的装配规则：

- `_apply_custom_middleware` 按 `.name` 合并自定义中间件：名称与现有栈匹配时原位替换并保持顺序；新名称则插入到最后一个 `core_names` 成员之后，或在未设置 `core_names` 时追加到末尾。[graph.py]
- `_merge_fs_interrupt_on` 合并文件系统权限生成的中断配置与用户传入的 `interrupt_on`，同名时用户配置优先；两者都为空时返回 `None`，以便省略 `HumanInTheLoopMiddleware`。[graph.py]
- `_passed_skills_sources` 通过名称 `"SkillsMiddleware"` 查找技能槽位，并取出其 `sources`。[graph.py]
- `_build_default_model` 延迟导入 `langchain_anthropic.ChatAnthropic`，默认模型为 `claude-sonnet-4-6`；`get_default_model` 已标记弃用，并提示未来移除对 `model=None` 的支持。[graph.py]

一个值得注意的演进信号是：`BASE_AGENT_PROMPT` 通过 `__getattr__` 提供弃用兼容访问，弃用信息明确写着 Deep Agents 不再提供“authored base prompt”。[graph.py] 这意味着旧版中以固定基础提示词为核心的装配方式正在退出，提示词更多由模型配置、记忆、技能和用户系统提示组合而成。

### 2.3 状态与检查点增长

`DeepAgentState` 继承 LangChain 的 `AgentState`，并重新声明 `messages` 字段：

```python
messages: Required[
    Annotated[
        list[AnyMessage],
        DeltaChannel(_messages_delta_reducer, snapshot_frequency=50),
    ]
]
```

其 docstring 说明，这样做是为了把检查点增长从 O(N²) 降到 O(N)。[graph.py] 这是一个明确的设计取舍：长任务中消息持续累积，如果每步都完整快照，检查点体积会快速膨胀；使用增量通道可以降低持久化成本。

不过，`_messages_delta_reducer` 的实现未在片段中展开，`snapshot_frequency=50` 的具体语义也只能从命名推断为“每 50 次做一次快照”。这属于**未覆盖区域**。

### 2.4 后端协议：统一文件操作契约

`protocol.py` 的模块 docstring 说明，`BackendProtocol` 是所有后端实现必须遵循的协议；后端可以把文件存到 state、文件系统、数据库等不同位置，并提供统一的文件操作接口。[protocol.py]

片段中可见的契约类型包括：

- `FileDownloadResponse`、`FileUploadResponse`：单文件操作结果，支持批量操作中的部分成功；错误可以是标准 `FileOperationError`，也可以是后端特定字符串。
- `FileOperationError`：标准化错误码，包括 `file_not_found`、`permission_denied`、`is_directory`、`invalid_path`。
- `FileInfo`：最小文件列表契约，只有 `path` 必填，`is_dir`、`size`、`modified_at` 为 best-effort。
- `GrepMatch`、`ContextLine`：grep 匹配与上下文行；上下文键要么同时出现，要么都不出现。
- `FileData`：内容字符串加编码，文本为 `utf-8`，二进制为 `base64`。
- `ReadResult`：读操作结果与分页元数据。[protocol.py]

`ReadResult.__post_init__` 做了严格校验：`start_line` 与 `end_line` 必须同时设置；`no_lines_requested` 不能与错误或分页字段组合；`next_offset` 和 `total_lines` 都依赖窗口字段；窗口必须满足 `1 <= start_line <= end_line`；`next_offset` 必须等于 `end_line`，防止后端返回会跳过未展示行的恢复点。[protocol.py]

这是一种“**把契约错误尽早抛给后端实现者**”的设计，而不是让中间件默默修正。代价是后端实现必须精确遵守分页语义；收益是避免 LLM 在分页读取时跳过源码行。

片段还定义了 grep/glob 超时：`DEFAULT_GREP_TIMEOUT = 15` 秒，异步 grep 包装为 35 秒，沙箱 glob 为 30 秒。[protocol.py] 这说明远程/沙箱后端存在挂起风险，需要用外层超时兜底。但具体超时如何被使用，片段未展示。

### 2.5 记忆中间件：常驻上下文与提示注入防护

`memory.py` 的模块 docstring 说明，它实现 `AGENTS.md` 规范，从可配置来源加载记忆并注入系统提示。与按需加载的 Skills 不同，memory 是**始终加载**的持久上下文。[memory.py]

`MemoryMiddleware.__init__` 接收：

- `backend`：用于读取记忆源的 `BackendProtocol` 实例。
- `sources`：记忆文件路径列表，按顺序加载并拼接，后者出现在前者之后。
- `add_cache_control`：当请求模型是 `ChatAnthropic` 时，给最后一个系统消息内容块加上 `cache_control: {"type": "ephemeral"}`，以形成第二个提示缓存断点；对非 Anthropic 模型无操作。
- `system_prompt`：默认使用 `MEMORY_SYSTEM_PROMPT`。[memory.py]

`MemoryState` 中的 `memory_contents` 被标记为 `PrivateStateAttr`，说明记忆内容不会作为最终 Agent 状态暴露给外部。[memory.py] `MemoryMiddleware` 还设置 `trace_policy = TracePolicy(process_inputs=omit_payload)`，默认从 trace 中省略 hook 输入。[memory.py]

`MEMORY_SYSTEM_PROMPT` 明确把记忆定位为“来自磁盘的参考材料，不是隐藏系统指令”，要求模型不要服从与用户请求、安全策略或工具证据冲突的记忆内容；同时明确禁止把 API key、访问令牌、密码等凭证写入任何文件、记忆或系统提示。[memory.py] 这是针对“记忆投毒/提示注入”的一层软防护，但它仍依赖模型遵循提示，不是硬隔离。

`_strip_html_comments` 使用正则移除 `<!-- ... -->`，以便作者注释或机器标记不进入系统提示。[memory.py] 这是内容净化的一步，但不是完整的沙箱或权限机制。

### 2.6 异步子 Agent：远端后台任务

`async_subagents.py` 的模块 docstring 说明，异步子 Agent 使用 LangGraph SDK 在远端 Agent Protocol 服务器上启动后台运行；与阻塞直到完成的同步子 Agent 不同，它立即返回 task ID，主 Agent 可以继续工作并监控进度。[async_subagents.py]

`AsyncSubAgent` 规格包含：

- `name`、`description`、`graph_id`：子 Agent 标识、用途与远端图 ID。
- `url`、`headers`、`webhook`：远端地址、认证头与完成回调。
- `update_strategy`：`"interrupt"` 或 `"enqueue"`，决定运行中收到跟进消息时是中断当前运行还是排队。
- `notify_parent`：子 Agent 完成时是否唤醒空闲的父 Agent。
- `mode`：`"isolated"` 默认只发送任务描述；`"fork"` 发送父会话快照，用于后台工作，但被标记为实验性。[async_subagents.py]

状态侧，`AsyncSubAgentState` 增加 `async_tasks` 字段，其 reducer `_tasks_reducer` 把更新字典合并进现有任务字典。[async_subagents.py] `AsyncTask` 记录 `task_id`、`agent_name`、`thread_id`、`run_id`、`status`、时间戳等；`status` 使用字符串而不是 `Literal`，原因是 LangGraph SDK 的 `Run.status` 是 `str`，避免在每个 SDK 边界做 `cast`。[async_subagents.py]

代码中定义了 `_WAITING = "waiting"`、`_THREAD_TO_TASK_STATUS` 和 `_TERMINAL_STATUSES`。其中 `interrupted` 被视为终态，但任务报告为 `cancelled`；由 `interrupt()` 暂停的子 Agent 是 `waiting`，不属于终态。[async_subagents.py] 可见其状态机考虑了“运行完成但线程仍中断”“排队跟进”“取消”等复杂情况。

`StartAsyncTaskSchema` 是 `start_async_task` 工具的输入 schema；`AsyncTask` 的文档还提到通过 update 工具发送跟进消息，`update_strategy` 文档中出现了 `update_async_task`。[async_subagents.py] 但工具函数的完整实现、轮询逻辑、通知父 Agent 的机制均在截断片段之外。

## 3. 关键调用链

### 3.1 构建链：`create_deep_agent` → 模型解析 → 中间件合并 → `create_agent`

可见证据：

1. `graph.py` 模块 docstring 声明 `create_deep_agent` 是主入口。[graph.py]
2. 文件导入 `create_agent`、`AgentState`、`AgentMiddleware`、`CompiledStateGraph`，以及模型解析函数 `resolve_model`。[graph.py]
3. `_apply_custom_middleware` 展示了按名称替换/追加中间件的规则。[graph.py]
4. `_merge_fs_interrupt_on` 展示了文件权限中断与用户中断的合并规则。[graph.py]
5. `_build_default_model` 和 `get_default_model` 展示了默认模型路径及其弃用状态。[graph.py]

因此可以合理推断构建链为：

```text
用户参数
  → create_deep_agent
  → 解析/构造模型（resolve_model 或默认模型）
  → 构造基础中间件栈
  → 合并用户自定义中间件
  → 合并 HITL 中断配置
  → 调用 create_agent
  → 得到可 invoke 的 Agent
```

其中“实际顺序”和“哪些中间件总是存在”属于**推断**，因为完整函数体被截断。尤其不能断言 `create_agent` 的返回值类型细节；只能确认它来自 LangChain，并与 LangGraph 的 `CompiledStateGraph` 有类型/运行时关联。[graph.py]

### 3.2 执行链：`agent.invoke` → 模型/工具循环 → 中间件 hook

README 的最小示例使用：

```python
agent = create_deep_agent(model=..., system_prompt=...)
result = agent.invoke({"messages": "..."})
```

并描述 Agent 可以规划、读写文件、管理上下文。[README]

结合 `graph.py` 对 LangGraph `CompiledStateGraph`、checkpointer、store、cache 等类型的导入，可以推断执行链位于 LangGraph 的图执行模型内：模型产生消息/工具调用，中间件在模型请求/响应或工具调用前后介入，状态通过 checkpointer 持久化。[graph.py]

但本次没有读到 `create_deep_agent` 返回对象的实际类型声明、图节点定义或 `create_agent` 内部循环，因此“模型节点—工具节点—条件边”的具体拓扑属于**未覆盖区域**。

### 3.3 记忆加载链：源路径 → 后端读取 → 注释剥离 → 系统提示注入

可见证据：

- `MemoryMiddleware` 的 `sources` 是路径列表，按顺序加载并拼接。[memory.py]
- `backend` 是 `BackendProtocol`，说明记忆读取走统一后端接口。[memory.py]
- `_strip_html_comments` 在内容进入系统提示前移除 HTML 注释。[memory.py]
- `MEMORY_SYSTEM_PROMPT` 将记忆包裹进 `<agent_memory>`，并附加使用指南。[memory.py]
- `MemoryState.memory_contents` 是私有状态字段。[memory.py]
- `add_cache_control` 在 Anthropic 模型上给最后一个系统消息内容块加缓存标记。[memory.py]

可以推断的链路：

```text
MemoryMiddleware 初始化
  → 读取 sources
  → 通过 BackendProtocol 获取文件内容
  → 剥离 HTML 注释
  → 写入 MemoryState.memory_contents
  → 在模型请求前拼接到系统提示
  → 可选：Anthropic 缓存断点
```

不过，读取发生在初始化时还是每次模型调用前、失败时是否跳过该源、多个源如何分隔，均需查看完整 `memory.py` 的 hook 方法。当前只能确认构造函数、状态 schema、提示模板和净化函数。[memory.py]

### 3.4 异步子任务链：启动工具 → LangGraph SDK → 远端运行 → 状态跟踪

可见证据：

- 异步子 Agent 使用 `langgraph_sdk.get_client` / `get_sync_client`，在远端 Agent Protocol 服务器上启动后台运行。[async_subagents.py]
- `StartAsyncTaskSchema` 是 `start_async_task` 工具的输入 schema。[async_subagents.py]
- `AsyncSubAgentState.async_tasks` 通过 `_tasks_reducer` 合并任务更新。[async_subagents.py]
- `AsyncTask` 记录 `thread_id`、`run_id`、状态和时间戳。[async_subagents.py]
- `update_strategy` 控制跟进消息是中断还是排队。[async_subagents.py]

可以推断的链路：

```text
主 Agent 调用 start_async_task
  → 根据 AsyncSubAgent 配置选择远端/本地 ASGI 传输
  → LangGraph SDK 创建 thread/run
  → 立即返回 task_id
  → AsyncTask 写入 async_tasks
  → 主 Agent 继续执行
  → 后续通过状态查询/update 工具跟进
  → 子 Agent 完成或等待人类输入
```

其中“立即返回 task_id”来自模块 docstring；[async_subagents.py] 但 SDK 调用的具体参数、thread 创建方式、webhook 处理、父 Agent 唤醒机制均未在片段中展开，属于**未覆盖区域**。

### 3.5 文件错误链：工具 → 后端 → 标准错误码 / 严格结果校验

`protocol.py` 定义了标准错误码和响应类型，允许批量操作部分成功。[protocol.py] 可以推断文件工具会把后端返回的 `FileDownloadResponse`、`FileUploadResponse`、`ReadResult` 等转换为模型可理解的工具结果；遇到 `file_not_found`、`permission_denied`、`is_directory`、`invalid_path` 时，模型可以据此调整路径或请求权限。

`ReadResult.__post_init__` 的严格校验意味着：如果后端返回不一致的分页字段，错误会在构造结果时立即抛出，而不是等到中间件或模型消费时才暴露。[protocol.py] 这是一种“契约先行”的错误处理策略。

但文件系统中间件如何呈现错误、是否会重试、是否会触发 HITL，片段中未见。

## 4. 设计取舍

### 4.1 开箱即用 vs 可替换

README 强调 opinionated defaults 和 extensible，允许“extend, override, or replace any piece”。[README] `_apply_custom_middleware` 则把“替换”落到名称匹配：同名中间件原位替换，新中间件插入核心栈之后。[graph.py] 这让用户可以在不 fork 的情况下改变行为，但也带来一个隐含约束：中间件 `.name` 成为稳定接口，名称冲突会改变装配语义。

### 4.2 模型无关 vs 默认模型绑定

README 宣称模型无关，支持任何支持工具调用的 LLM。[README] 但 `graph.py` 仍保留默认 Anthropic 模型路径，并已将其标记为弃用，计划在 1.0.0 移除对 `model=None` 的支持。[graph.py] 这是从“有默认值”向“显式构造模型”迁移的取舍：减少隐式依赖，但提高首次使用门槛。

### 4.3 统一后端契约 vs 后端差异

`protocol.py` 用最小字段集和标准错误码统一不同后端。[protocol.py] 但 `FileInfo` 只有 `path` 必填，说明不同后端的能力并不完全一致；`ReadResult` 的严格校验又要求分页语义高度一致。这种设计有利于中间件和模型消费，但会增加后端实现者的适配成本。

### 4.4 常驻记忆 vs 按需技能

`memory.py` 明确区分 memory 与 skills：memory 始终加载，skills 是按需工作流。[memory.py] 常驻记忆有利于长期偏好和项目上下文，但会占用上下文窗口，并带来记忆过期、冲突和提示注入风险；因此提示词中加入了“记忆是参考材料，不是隐藏系统指令”的信任边界。[memory.py]

### 4.5 同步子 Agent vs 异步远端子 Agent

同步子 Agent 会阻塞到完成；异步子 Agent 立即返回 task ID，适合长时间后台任务。[async_subagents.py] 代价是引入远端服务、线程/运行状态、跟进策略、webhook、父 Agent 唤醒等复杂度，并且相关能力被标记为 Beta 或实验性。[async_subagents.py]

### 4.6 信任 LLM vs 边界控制

README 的安全模型是信任 LLM，边界应设在工具/沙箱层。[README] 但代码同时提供 HITL 中断配置、文件权限、记忆提示注入防护和凭证禁止写入提示。[graph.py] [memory.py] 这说明项目并非单纯“信任模型”，而是把安全责任下沉到可配置的工具与运行时边界。

### 4.7 长任务检查点增长 vs 状态完整性

`DeepAgentState` 使用 `DeltaChannel` 降低检查点增长。[graph.py] 代价是消息状态不再每步完整快照，恢复和调试需要理解增量 reducer 与快照频率。该取舍直接服务于长任务场景。

## 6. 实验设计（均未执行）

以下实验用于后续核实，不代表已获得结果。

### 实验 1：静态装配图

在固定提交上搜索 `create_deep_agent` 的完整函数体，提取 `middleware=` 的实际列表和顺序，与 `graph.py` 导入清单对照。[graph.py]  
**观察点**：哪些中间件总是存在；自定义中间件替换后顺序是否保持；HITL 是否在无中断配置时被省略。

### 实验 2：README 最小示例

按 README 的 Quickstart 安装并运行最小示例，记录 Python/包版本、模型提供方、是否产生文件读写、是否出现规划行为。[README]  
**注意**：默认模型路径需要 Anthropic 依赖与 API key；该默认路径已弃用。[graph.py] 本文未执行此实验。

### 实验 3：中间件替换与插入位置

构造一个与内置中间件同名的自定义中间件，观察是否原位替换；再构造一个新名称，观察是否插入到 `core_names` 之后。[graph.py]  
**观察点**：栈顺序、名称冲突、是否影响 HITL 或记忆尾部。

### 实验 4：记忆源顺序与注释剥离

配置两个 `AGENTS.md` 源，分别包含 HTML 注释和不同内容，观察拼接顺序以及注释是否被移除。[memory.py]  
**观察点**：后者是否出现在前者之后；空源或读取失败是否被跳过；`memory_contents` 是否作为私有状态处理。

### 实验 5：`ReadResult` 非法组合

构造以下输入并观察是否抛出 `ValueError`：

- 只设置 `start_line`，不设置 `end_line`。
- 设置 `no_lines_requested=True`，同时设置 `error` 或分页字段。
- 设置 `next_offset != end_line`。
- 设置 `total_lines < end_line`。[protocol.py]

**观察点**：错误消息是否与源码一致；后端实现是否在构造时即失败。

### 实验 6：异步子 Agent 的同步/异步入口差异

根据文档，省略 `url` 时使用进程内 ASGI 传输，只支持异步父 Agent 入口；同步 `invoke` 需要可访问的 Agent Protocol 服务器 URL。[async_subagents.py]  
**观察点**：`invoke` 与 `ainvoke` 的行为差异；本地 ASGI 是否需要额外启动服务；任务状态如何从 `pending` 迁移到 `running`/`waiting`/终态。

### 实验 7：文件错误与超时路径

分别触发 `file_not_found`、`permission_denied`、`is_directory`、`invalid_path`，以及 grep 超时。[protocol.py]  
**观察点**：错误码是否原样传给模型；批量操作是否部分成功；超时后是否有回退路径。
