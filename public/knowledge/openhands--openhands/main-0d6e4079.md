## 2. 基于已读代码的架构

### 2.1 分层草图

```text

       ├─ MARS Web Bridge 安装（installMarsWebBridge）

       ├─ DEV 预览种子（installPendingChatPreview）

  └─ src/query-client-config.ts
       ├─ createAgentServerQueryClient()
       │    ├─ QueryCache: 成功上报 backend 健康；失败处理 401 与 toast
       │    └─ MutationCache: 失败处理 401 与 toast
```

### 2.2 客户端启动层

`src/entry.client.tsx` 是客户端水合入口，使用 `react-router/dom` 的 `HydratedRouter` 与 `react-dom/client` 的 `hydrateRoot`，来源：[src/entry.client.tsx](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/src/entry.client.tsx)。

启动顺序是明确的：

1. `prepareApp()` 首先 `await Promise.all([waitForI18n(), installMarsWebBridge()])`。注释说明 MARS Bridge 只在服务端托管 `scripts/mars-web-bridge.mjs` 时存在，且必须在渲染前完成，因为 UI 会同步读取 `window.marsBridge`，来源：[src/entry.client.tsx](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/src/entry.client.tsx)。
2. 若 `shouldStartMockWorker()` 为真，动态导入 `./mocks/browser` 并调用 `worker.start({ onUnhandledRequest: "bypass" })`，来源同上。
3. 开发模式下动态导入 `./dev/seed-pending-chat-preview` 并安装预览种子，来源同上。
4. `prepareApp().then(...)` 中通过 `startTransition` 执行 `hydrateRoot`，树为 `StrictMode > AgentServerUIProviders > HydratedRouter`，并传入 `analytics={DEFAULT_AGENT_SERVER_ANALYTICS}`、`withStyleRoot={false}`，来源同上。

两个可直接观察到的设计点：

- 文件头注释仍写着 “Remix will handle hydrating”，但实际导入的是 React Router 的 `HydratedRouter`。这说明代码经历了 Remix → React Router 的迁移，注释是遗留文本，来源：[src/entry.client.tsx](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/src/entry.client.tsx)。
- `prepareApp().then(...)` **没有 `.catch`**。〔推断〕如果 i18n、MARS Bridge 或 mock worker 初始化抛错，水合不会发生，页面可能停留在未挂载状态；片段中未见兜底渲染或错误上报。该判断仅基于已读片段，未覆盖入口之外的全局错误边界。

### 2.3 数据访问层：可切换的 QueryClient

`src/query-client-config.ts` 定义了一个可替换的全局 QueryClient 体系，来源：[src/query-client-config.ts](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/src/query-client-config.ts)。

核心结构：

- `createAgentServerQueryClient()`：工厂函数，创建带 `QueryCache` 与 `MutationCache` 的 `QueryClient`。
- `defaultQueryClient`：模块级懒加载单例；在 `DEV` 或 `VITE_MOCK_API === "true"` 时挂到 `window.__OH_QUERY_CLIENT__`，便于调试，来源同上。
- `activeQueryClient`：可选的活动客户端；`getQueryClient()` 返回 `activeQueryClient ?? getDefaultQueryClient()`。
- `setQueryClient(client?)`：设置活动客户端；传空则回落到默认客户端。
- `queryClient`：`Proxy`，每次属性访问都转发到 `getQueryClient()`，并把函数绑定到真实 client 上，来源同上。

这意味着业务代码可以统一 `import { queryClient }`，而底层仍支持按后端切换实例。〔推断〕这与 README 中“在多个 Agent 后端之间切换”的产品能力相呼应，但切换发生的具体位置未在已读片段中出现。

### 2.4 错误处理与后端健康

Query 与 Mutation 的错误处理并不对称，这是阅读时最值得注意的细节：

| 场景 | QueryCache | MutationCache |
| --- | --- | --- |
| 401 | 非认证查询会调用 `handle401Error`，使 `["user","authenticated"]` 失效 | 同样调用 `handle401Error` |
| 认证查询自身 | 通过 `isAuthQuery` 排除，避免再次触发失效 | 不适用 |
| Toast | 受 `meta.disableToast` 控制；相同错误消息 3 秒内去重 | 受 `disableToast` 控制；**没有 3 秒去重** |
| 云后端认证错误 | `isActiveCloudBackendAuthError` 为真时静默 | 同样静默 |
| 成功 | 若 `query.meta.backendId` 是字符串，调用 `recordBackendSuccess(backendId)` | 不适用 |

来源：[src/query-client-config.ts](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/src/query-client-config.ts)。

`isActiveCloudBackendAuthError` 的判定条件很具体：必须是 `AxiosError`、状态码 401、当前活动后端 `kind === "cloud"`，且请求 URL 为空或以该后端 `host` 开头，来源同上。〔推断〕其意图是：云后端自身的 401 应由云侧认证流程处理，而不是弹出通用错误提示；但“云侧如何处理”不在已读片段中。

`retryDelay: getQueryRetryDelay` 的注释说明其目的：带抖动的指数退避，并在确认 429 时增加额外退避，避免多个标签页同时刷新导致同步重试、再次触发限流，来源同上。注意片段只覆盖了 `retryDelay`，未设置 `retry` 次数。

### 2.5 发布更新检查

`src/api/agent-canvas-updates.ts` 把“是否有更新版本”的数据源隔离在单一模块：

- `NPM_LATEST_VERSION_URL = "https://registry.npmjs.org/@openhands/agent-canvas/latest"`。
- `fetchLatestAgentCanvasVersion(signal?)` 使用 `fetch` 请求该 URL，`!response.ok` 抛错，解析 JSON 后要求 `version` 为非空字符串，返回 `trim()` 结果。
- 导出 `AGENT_CANVAS_RELEASE_NOTES_URL` 与 `AGENT_CANVAS_UPDATE_COMMANDS`（npm 与 docker 两条字面命令），命令显式注明“不本地化”。

来源：[src/api/agent-canvas-updates.ts](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/src/api/agent-canvas-updates.ts)。

这个模块只负责“取最新版本号”，**不做版本比较、不缓存、不带超时**；`signal` 由调用方传入。文件注释明确说它被隔离出来，以便发布渠道变化（例如改为 GitHub Releases）时不改查询 hook 或设置页更新卡片，来源同上。注意：查询 hook 与设置卡片本身未被读取，属于注释提及但未覆盖的区域。

## 3. 关键调用链

### 3.1 启动与水合链

```text
加载 src/entry.client.tsx
  → prepareApp()
      → Promise.all([waitForI18n(), installMarsWebBridge()])
      → shouldStartMockWorker() ?
           import("./mocks/browser") → worker.start({ onUnhandledRequest: "bypass" })
      → import.meta.env.DEV ?
           import("./dev/seed-pending-chat-preview") → installPendingChatPreview()
  → .then(startTransition(() => hydrateRoot(...)))
      → StrictMode
          → AgentServerUIProviders(analytics, withStyleRoot=false)
              → HydratedRouter
```

来源：[src/entry.client.tsx](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/src/entry.client.tsx)。

关键顺序约束：i18n 与 MARS Bridge 必须在渲染前 settle；mock worker 在渲染前启动；DEV 种子只在开发模式安装。

### 3.2 查询成功链：后端健康上报

```text
业务代码访问 queryClient.<method>
  → Proxy get
      → getQueryClient()
          → activeQueryClient ?? getDefaultQueryClient()
              → createAgentServerQueryClient()
  → 请求成功
      → QueryCache.onSuccess(data, query)
          → backendId = query.meta?.backendId ?? query.options.meta?.backendId
          → typeof backendId === "string" ? recordBackendSuccess(backendId)
```

来源：[src/query-client-config.ts](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/src/query-client-config.ts)。

这说明查询可以通过 `meta.backendId` 参与后端健康状态记录；具体哪些查询设置了该 meta，未在片段中覆盖。

### 3.3 查询失败链：401、Toast 去重与云后端静默

```text
QueryCache.onError(error, query)
  → 若 queryKey 是 ["user","authenticated"]：跳过 handle401Error
    否则 handle401Error(error, client)
        → 状态 401 ? invalidateQueries({ queryKey: ["user","authenticated"] })
  → disableToast = query.meta?.disableToast ?? query.options.meta?.disableToast
  → 若 !disableToast 且 !isActiveCloudBackendAuthError(error)
      → errorMessage = retrieveAxiosErrorMessage(error)
      → 若 shownErrors 不含该消息
          → displayErrorToast(errorMessage || i18n.t(ERROR$GENERIC))
          → shownErrors.add(...)
          → 3 秒后删除
```

来源：[src/query-client-config.ts](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/src/query-client-config.ts)。

`Handle401Error` 对认证查询本身做了排除，〔推断〕是为了避免“认证查询失败 → 使认证查询失效 → 再次请求 → 再次失败”的循环；片段中未见显式注释说明该意图。

### 3.4 Mutation 失败链

```text
MutationCache.onError(error, _, __, mutation)
  → handle401Error(error, client)
  → disableToast = mutation?.meta?.disableToast ?? mutation?.options.meta?.disableToast
  → 若 !disableToast 且 !isActiveCloudBackendAuthError(error)
      → displayErrorToast(retrieveAxiosErrorMessage(error) || i18n.t(ERROR$GENERIC))
```

来源：[src/query-client-config.ts](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/src/query-client-config.ts)。

与 Query 的差异是：Mutation 没有 `shownErrors` 去重，因此连续失败的 mutation 可能连续弹 toast；这是代码事实，是否需要优化取决于产品预期。

### 3.5 版本检查链

```text
调用方（未读取）
  → fetchLatestAgentCanvasVersion(signal?)
```

## 4. 设计取舍

| 取舍 | 代码证据 | 收益 | 代价 / 风险 |
| --- | --- | --- | --- |
| 全局可替换 QueryClient + Proxy | `activeQueryClient`、`setQueryClient`、`queryClient` Proxy，来源：[query-client-config.ts](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/src/query-client-config.ts) | 业务代码统一入口；支持按后端切换实例；无需层层传 client | 全局可变状态；测试隔离与生命周期管理更复杂；Proxy 每次访问都解析当前 client |
| 懒加载默认单例 | `getDefaultQueryClient()` 首次调用才创建 | 避免模块加载即创建缓存；便于按需初始化 | 首次请求有初始化成本；DEV 下暴露 `window.__OH_QUERY_CLIENT__` |
| 查询错误 3 秒去重 | `shownErrors` + `setTimeout` | 抑制同一错误在短时间内的 toast 风暴 | 不同操作产生相同文案时会被误抑制；Mutation 未采用同一策略 |
| 云后端 401 静默 | `isActiveCloudBackendAuthError` | 避免云认证流程与通用错误提示冲突 | 判定依赖 `AxiosError` 与 host 前缀匹配；非 Axios 错误不会被静默 |
| 429/抖动退避 | `retryDelay: getQueryRetryDelay` 注释 | 降低多标签页同步重试造成的二次限流 | 仅覆盖 `retryDelay`，未在片段中约束重试次数 |
| 更新源隔离 | 文件注释明确“isolated here so the release channel can change”，来源：[agent-canvas-updates.ts](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/src/api/agent-canvas-updates.ts) | 渠道变更不影响 hook/UI | 模块无缓存、无超时，依赖调用方传 `signal` |
| 精确版本锁定 | `package.json` 依赖多为精确版本，无 `^`，来源：[package.json](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/package.json) | 可复现构建；减少供应链漂移 | 升级需显式改动；与 README 中 npm 发布年龄过滤策略共同强调可复现性 |
| 安全默认 loopback | README：本地监听仅绑定 `127.0.0.1`，session key 自动注入；`--host 0.0.0.0` 时不注入，Docker 默认也不注入，来源：[README.md](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/README.md) | 降低本地 session key 暴露风险 | 跨机访问需显式配置并改用 API key 入口 |
| 双分发面（CLI + 组件库） | `bin` 与 `exports` 同时存在，来源：[package.json](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/package.json) | 既可独立运行，也可嵌入宿主 | 构建产物与导出边界需要持续维护；`files` 同时包含 `dist`、`build`、`bin`、`config`、`scripts`、`tools` |

一个容易被忽略的取舍：`entry.client.tsx` 在渲染前阻塞等待 i18n 与 MARS Bridge。这换来了“UI 可同步读取 `window.marsBridge`”的简单契约，但也让任一初始化失败都可能阻塞水合，且片段中未见 `.catch` 兜底，来源：[entry.client.tsx](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/src/entry.client.tsx)。〔推断〕生产环境可能依赖外层错误边界或构建期保证，但未在已读代码中体现。

- 产出：画出“前端 / Agent Server / 沙箱 / 外部后端”的部署草图。注意 README 是唯一部署证据，未读取 `bin/` 与 `docker/`。

### 第 2 步：从 `package.json` 建立“入口地图”

- 核对 `bin`、`exports`、`main/module/types`、`files`、`peerDependencies`，来源：[package.json](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/package.json)。

- 产出：列出“应用入口”和“库入口”各自的构建路径。`build:lib` 与 `BUILD_LIB=true vite build` 说明库构建是独立流程。

### 第 3 步：读懂客户端启动顺序

- 逐行阅读 `src/entry.client.tsx`，标注每个 `await` 的先后依赖，来源：[entry.client.tsx](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/src/entry.client.tsx)。

## 6. 实验设计（均未执行）

> 以下为基于已读代码的验证方案，不代表已运行或已得到结果。

### 实验 A：验证启动阻塞与失败路径

- 目标：确认 `prepareApp()` 任一 await 失败时是否真的阻止水合。
- 方法：在本地开发环境对 `waitForI18n` 或 `installMarsWebBridge` 注入延迟/拒绝，观察根节点是否为空、控制台是否有未捕获 rejection。
- 依据：`prepareApp().then(...)` 无 `.catch`，来源：[entry.client.tsx](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/src/entry.client.tsx)。
- 预期：〔推断〕拒绝时 `hydrateRoot` 不执行；若外层有错误边界，表现可能不同。

### 实验 B：观察 Query 错误 toast 去重

- 目标：验证 `shownErrors` 的 3 秒窗口。
- 方法：在 `VITE_MOCK_API=true` 或 DEV 下，通过 `window.__OH_QUERY_CLIENT__` 触发两个相同错误消息的查询失败，记录 toast 数量与时间。
- 依据：DEV 或 mock 模式暴露 `window.__OH_QUERY_CLIENT__`，来源：[query-client-config.ts](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/src/query-client-config.ts)。
- 注意：需要先确认 mock 层是否已有可复用的失败 handler；`src/mocks` 未读取。

### 实验 C：对比 Query 与 Mutation 的 toast 行为

- 目标：确认 Mutation 是否真的没有去重。
- 方法：连续触发两次相同错误的 mutation，观察是否出现两条 toast。
- 依据：`MutationCache.onError` 未使用 `shownErrors`，来源：[query-client-config.ts](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/src/query-client-config.ts)。

### 实验 D：单元测试 `fetchLatestAgentCanvasVersion` 的错误分支

- 目标：覆盖 `!response.ok` 与缺失/空白 `version`。
- 方法：mock 全局 `fetch`，分别返回 500、`{}`、`{ version: "  " }`、`{ version: "1.2.3" }`，断言抛错或返回 trim 后的值。
- 依据：函数对 `response.ok` 与 `version` 类型/空白有显式检查，来源：[agent-canvas-updates.ts](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/src/api/agent-canvas-updates.ts)。
- 说明：项目已配置 Vitest，来源：[package.json](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/package.json)；但本实验未执行。

### 实验 E：验证后端健康上报条件

- 目标：确认只有 `meta.backendId` 为字符串时才调用 `recordBackendSuccess`。
- 方法：构造带/不带 `meta.backendId` 的查询，mock `recordBackendSuccess`，观察调用次数。
- 依据：`QueryCache.onSuccess` 的类型判断，来源：[query-client-config.ts](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/src/query-client-config.ts)。
- 注意：`recordBackendSuccess` 的真实副作用未读取。
