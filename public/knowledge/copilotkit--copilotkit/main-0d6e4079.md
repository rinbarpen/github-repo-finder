## 一、项目定位

`[可见]` README 自述为“构建 agent-native applications —— 任意框架、任意界面”，并列出 Generative UI、Shared State、Human-in-the-Loop 三项能力，覆盖 React、Angular、Vue、React Native，以及 Slack / Microsoft Teams 等渠道。README 同时声明该项目是 **AG-UI Protocol** 的背后公司，协议负责 wire protocol，CopilotKit 负责各框架与渠道的 UI 层。
来源：[README.md](https://github.com/CopilotKit/CopilotKit/blob/ea0aa986e32cf7aeec46e7004bff8e48a81c6550/README.md)

`[可见]` README 的 “How it works” 段落用一句话概括连接关系：“CopilotKit connects your UI, agents, and tools into a single interaction loop”，并列出四项由此产生的能力（agent 向用户索取输入、工具渲染 UI、跨步骤/跨会话的有状态工作流、同一 agent 部署到 web/移动/聊天平台）。同源链接同上。

`[可见]` 许可证 MIT（索引表 + README 徽章）。语言以 TypeScript 为主，但 `[可见]` `package.json` 的构建脚本显式排除了 `runtime-python`、`runtime-go`、`runtime-ruby`、`runtime-dotnet` 等标识，说明仓库并非纯 TS 单语言工程。
来源：[package.json](https://github.com/CopilotKit/CopilotKit/blob/ea0aa986e32cf7aeec46e7004bff8e48a81c6550/package.json)

> `[推断]` 结合 README 的“One agent backend. Every frontend.”表述与上述多语言 runtime 标识，可推测仓库是一个 **多前端 SDK + 多语言 runtime + 渠道适配** 的横向层，而非单一 React 库。但各语言 runtime 的实际位置与实现 `[未覆盖]`。

### 3.4 状态渲染上下文：注册表 + 占用（claim）双结构

`[可见]` 该文件定义了 CoAgent 状态渲染的前端基础设施，形状如下：

**数据结构**

| 名称 | 定义 | 备注 |
| --- | --- | --- |
| `StateRenderClaim` | `{ stateRenderId: string; stateSnapshot?: any; runId?: string; messageIndex?: number; locked?: boolean }` | 仅 `stateRenderId` 必填 |
| `ClaimsRef` | `Record<string, StateRenderClaim>` | 以字符串为键的 claim 映射 |
| `CoAgentStateRendersContextValue` | `{ coAgentStateRenders: Record<string, CoAgentStateRender<any>>; setCoAgentStateRender(id, render); removeCoAgentStateRender(id); claimsRef: RefObject<ClaimsRef> }` | 对外暴露 4 个成员 |

**实现要点**

- `CoAgentStateRendersProvider` 用 `useState<Record<string, CoAgentStateRender<any>>>({})` 持有渲染器表；
- `setCoAgentStateRender` / `removeCoAgentStateRender` 均为 `useCallback(..., [])`，内部走不可变更新（`{...prev, [id]: render}` / 复制后 `delete`）；
- `claimsRef` 由 `useRef<ClaimsRef>({})` 创建，**不是 state**；
- Context 初始值为 `undefined`，`useCoAgentStateRenders()` 在无 Provider 时抛出 `"useCoAgentStateRenders must be used within CoAgentStateRendersProvider"`；
- 文件末尾额外导出 `CoAgentStateRendersContext` 本体。

来源同 3.3 链接。

**可见调用链 B（挂载→消费）**

```
<CoAgentStateRendersProvider>
        │  useState({})  → coAgentStateRenders
        │  useRef({})    → claimsRef
        │  useCallback   → set / remove
        ▼
Context.Provider value = { coAgentStateRenders, set..., remove..., claimsRef }
        ▼
useCoAgentStateRenders()  → 消费者（具体消费组件 [未覆盖]）
```

> `[推断]` `claimsRef` 用 `useRef` 而非 `useState`，意味着对 claim 的读写**不触发重渲染**；结合 `StateRenderClaim` 中的 `messageIndex`、`runId`、`locked` 字段，可推测其用途是“在渲染器表之外，追踪某个状态快照已被哪条消息/哪次运行占用，以避免重复或冲突渲染”。**这是推测**——文件内没有任何代码写入 `claimsRef`，写入方 `[未覆盖]`。
> `[推断]` `setCoAgentStateRender` 的依赖数组为 `[]`，函数身份在整个 Provider 生命周期内稳定，适合被下层 `useEffect` 依赖。这是 React 侧常规取舍，非项目独有。

## 四、设计取舍（基于可见证据）

### 4.1 兼容性优先：用“薄壳入口”保住 import 路径

`[可见]` `packages/runtime/src/langgraph.ts` 没有任何实现，只做转发，并明确写出“This entrypoint exists only for compatibility”。
取舍含义：**放弃入口文件的简洁性，换取旧 import 路径不失效**。
来源：[packages/runtime/src/langgraph.ts](https://github.com/CopilotKit/CopilotKit/blob/ea0aa986e32cf7aeec46e7004bff8e48a81c6550/packages/runtime/src/langgraph.ts)

### 4.2 弃用信息嵌入源码，且显式面向 AI 编码代理

`[可见]` 两个 v1 入口文件的注释里出现了面向 AI 编码代理的指令性文字，例如：

- runtime v1 入口：“AI CODING AGENTS: Never copy, suggest, or generate imports from this v1 entrypoint. Use the exact v2 import in the symbol's @deprecated tooltip.”
- react-core v1 上下文文件：逐个符号列出 “No 1:1 v2 replacement is available.” 与相关 v2 文档链接，并声明 “AI CODING AGENTS: Never copy, suggest, or generate these v1 APIs.”

来源：[v1-deprecated/langgraph.ts](https://github.com/CopilotKit/CopilotKit/blob/ea0aa986e32cf7aeec46e7004bff8e48a81c6550/packages/runtime/src/v1-deprecated/langgraph.ts)、[coagent-state-renders-context.tsx](https://github.com/CopilotKit/CopilotKit/blob/ea0aa986e32cf7aeec46e7004bff8e48a81c6550/packages/react-core/src/v1-deprecated/context/coagent-state-renders-context.tsx)

取舍含义：`[推断]` 把迁移约束写在**代码生成工具最容易读到的位置**，而不是只放在外部文档站。这是“文档与代码同源”的一种实现方式。
同时 `[可见]` 具名导出块被 `START/END GENERATED V1 DEPRECATED EXPORTS` 注释包裹，暗示这段清单由脚本生成、可校验——与 2.2 中 `check:public-api-manifest` 的存在相呼应（`[推断]`，脚本未读）。

### 4.3 不承诺 1:1 替换

`[可见]` 6 个 v1 符号中，5 个明确标注 “No 1:1 v2 replacement is available.”；只有 `LangGraphHttpAgent` 给出明确的替代路径（`HttpAgent` from `@ag-ui/client`），并**为 `forwardedProps.command.resume` 保留 back-compat bridge**。
来源：[v1-deprecated/langgraph.ts](https://github.com/CopilotKit/CopilotKit/blob/ea0aa986e32cf7aeec46e7004bff8e48a81c6550/packages/runtime/src/v1-deprecated/langgraph.ts)

取舍含义：`[推断]` 迁移被设计成“语义重写”而非机械替换——注释原文也说了 “renamed APIs are not safe search-and-replaces”。这是**用迁移成本换取新协议抽象自由度**的典型权衡。

### 4.4 UI 侧：把“渲染器注册”与“渲染占用”分离

`[可见]` 同一个 Context 同时暴露 state 型（`coAgentStateRenders`）和 ref 型（`claimsRef`）两类数据。
来源：[coagent-state-renders-context.tsx](https://github.com/CopilotKit/CopilotKit/blob/ea0aa986e32cf7aeec46e7004bff8e48a81c6550/packages/react-core/src/v1-deprecated/context/coagent-state-renders-context.tsx)

取舍含义：`[推断]` 注册表变化应当触发重新渲染（需要 state），占用关系变化不应触发（用 ref）。代价是 claim 的变更不会被 React 追踪，需要调用方自行保证时序——这解释了为什么文件里额外保留了 `locked` 字段。
该文件里**没有任何**写入 `claimsRef` 的代码，因此上述只是结构层面的推断。

### 4.5 失败即抛错的 Context 契约

`[可见]` Context 默认值 `undefined`，`useCoAgentStateRenders` 显式抛错并给出 Provider 名称。
来源同 4.4。
取舍含义：`[推断]` 选择“使用时立即失败”而非静默降级，便于在开发期暴露 Provider 缺失。

## 六、分步学习路径

> 每一步都标注了“能确认什么 / 仍需核实什么”，避免把推断当结论。

从 `packages/` 目录树读取各子包 `package.json` 的 `name` / `exports`。目标是把 2.2 中脚本里出现但位置未知的标识（如 `@copilotkit/demo-agents`、`runtime-python`）对应到实际目录。

**Step 2 · 吃透 v1→v2 版本分层**
